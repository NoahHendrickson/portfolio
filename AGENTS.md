## Architecture

Single-page React 19 + Vite 8 portfolio. There is **no router library** — `src/App.tsx` reads `window.location.pathname` and switches the rendered tree. Internal links use hrefs like `/work/invisible` via `AppLink` / `navigate`. When adding a new route, extend the conditional in `App.tsx` and link to `/your-route`. Legacy `#/…` bookmarks are rewritten to pathnames on boot.

The route is read through `useSyncExternalStore(subscribeToRoute, getRoute)` rather than a `useState` + listener effect, because a page that redirects from its **own mount effect** fires `routechange` before an effect in `App` could have subscribed. `useSyncExternalStore` re-reads after subscribing, so that update isn't dropped; with the listener in an effect it was, and the redirect left a blank page. `navigate(path, { replace })` is for those same self-redirects: pushing the page being bounced away from would only send the visitor forward again on Back.

Routes:

| Route | Renders |
|---|---|
| `/` | The home page — a vertical hover-tab rail beside one content panel (see below) |
| `/work` | Redirects to `/` with the Work tab pre-activated (old links and project Back pills point here) |
| `/work/<slug>` | `ProjectStory` if `projects[slug].landing` is set, otherwise `ProjectLanding` (`src/data/projects.ts`) |
| `/work/invisible` | Redirects like `/work` (the old case-study index is gone) |
| `/work/invisible/onboarding` | `InvisibleOnboarding` — the Meridial onboarding case study |
| `/work/invisible/synapse` | `InvisibleSynapse` — the Synapse 0-1 launch case study |
| `/work/invisible/apply` | `InvisibleApply` — the Meridial apply-to-projects case study |

The home page is the **vertical-tab layout** from the July 2026 file (section `321:38613`, frames `320:30803` Me / `320:30968` Work): `HomeRail` on the left — Me, Work, How I design, Where I've been, Contact, LOLs — and whichever panel the active tab selects in a column beside it. **Hovering an entry switches the panel** (sticky — it stays after the mouse leaves) and clicking commits the same switch, which is the only affordance on touch. Nothing routes: the whole page lives on `/`, and the active tab is sessionStorage (`src/homeTab.ts`), so it survives refresh and Back from a project page but a shared link always opens on Me. The legacy `/work` routes land on home with Work active — `App` flips the tab during render (the `prevRoute` adjustment) before the effect replaces the URL, so the redirected-to page never paints the previous tab first. Panels: Me is `ProfileRow` (still exported from `Header`) over `Hero`; Work is `WorkList`; How I design / Where I've been / LOLs are `DesigningNow` / `PreviousRoles` / `LlmQuotes`, the three sections `Experience.tsx` now exports instead of one stacked page; Contact is `ContactPanel`, the same email / LinkedIn / GitHub set the header's `ContactMenu` drops down, with the copy-and-check email row.

The arrow only shows in the mobile dropdown now. Every glyph on the rail, the arrow and the mobile caret pair included, is `PixelGlyph` — 2px squares read off the frame's rects — rather than an exported SVG. The active pill slides along the spine (`RailList`'s stretch-and-follow animation, tuned in `index.css`'s `.rail-pill` rules), up/down arrow keys walk the tabs when the rail has focus, and mobile swaps the rail for a dropdown off the active pill. The frame's second Work rail and cream sheet (`365:6192`) were tried and backed out; in their place the **Work menu** (`373:12390`, the card at `373:12447`) unfolds *in the rail's flow* under the Work pill — a white card 16 off the spine and the rows either side, 8 inside, with the Work face at its top and a row per section (label and its count) — and the tabs below ride down with it. The card is `FilterMenu`; `RailList` takes it as `menu={{ at, node }}` and renders it in a `.rail-menu` grid row easing `0fr → 1fr` on the pill's trail curve. Because the menu sits between two buttons, the pill's ink copies are seated at each button's **measured** top (`seatFor`), the list is the rail's full height so `bottom` holds still while the menu unfolds, and the seat is measured where the menu is *going* rather than where it is. The sections and the cards they hold live in `src/data/workCards.ts` (`WORK_FILTERS`, ids unchanged so a stored `work-filter` stays valid; Career is labelled "Case studies" per the frame), `App` holds the filter beside the tab, and `WorkList` shows its pill row only on mobile, where the rail is a dropdown and there is no menu. **Keys:** while focus is in the rail, the arrows walk one list — Hi, Work/All … Work/Graphic design, Where I've been, … — stepping onto Work from above lands on its first section and from below its last (hover and click keep the section as it was). A press from the panel is left alone so that scroller can move. The frame's key caps were not built. The rail labels run 16px against both frames' 20 — a standing choice, so the menu rows match it.

`App.tsx` is one normally-scrolling dark page. `ShaderPanel` now just renders `LeafPattern` — a static pixel-art leaf field (opaque PNG tiles on a brick-stagger lattice, 117×81 a leaf) absolutely positioned top-right, running 260vh past the fold and thinning out; the page scrolls over the same dark shell underneath. The content column is a `vw` share per tab (`CONTENT_PCT`: 70 by default, 84.4 on Work) with the panel capped at `PANEL_MAX` (700px, or 937px on Work) — the leaf field anchors at the column's edge so the wider Work column slides over it, and `LEAF_STRIP_MAX` pins the strip's width on big screens. Below `TABLET_MAX` the column grows (`THIN_GROW`) so a ~1100px window is not stuck with a narrow measure beside a third of the viewport of leaves; at tablet and up the 1512 frame does not move. Because `vw` shares keep widening on a big screen while the copy stays on its own measure, `src/layout.ts` grows the **left gutter** past the design width: `shellPad()` is `max(pageGutter(), (100vw − SHELL_MAX) / 2)` with a single `SHELL_MAX` of 1600 (`ProjectStory`'s cap, the site's widest page). There is deliberately one shared formula, anchored to `100vw` rather than the container, so **every route resolves the same left edge at any viewport width**. The right side stays on the plain `pageGutter()`. `pageGutter()` is the 120 held flat from `TABLET_MAX` (1366, iPad Pro landscape) up and scaled in proportion below it.

`Header` is now only the project pages' chrome: a Back pill (`leading="back"`) with `ContactMenu` pinned right, plus the profile row `showProfile` controls (the home page reaches `ProfileRow` directly instead). `TabBar` still exists but only the cream `ProjectLanding` renders it, via `Header`'s default `leading="tabs"` — its `/work` href resolves through the redirect.

`Footer.tsx` is **not mounted anywhere** — commit `7627598` removed it sitewide and left the component file in place. The story frames in Figma still draw it, so a frame ending in a Back to / Jump to / Get in touch block is expected to diverge. What follows describes the component as built, should it ever come back. It comes from the July 2026 file (node `58:2190`): three columns on an 80px pad with a 120px gutter, Back to / Jump to / Get in touch. It runs the **full page width**. The email row copies to the clipboard and confirms with a check rather than navigating, and "Moonfang Armory" points at the live site because `/work/armory` still falls through to the cream `ProjectLanding`.

Project pages come in two layouts. `ProjectLanding.tsx` is the generic one — stats row, `label`-railed sections, stack and status grids — and is still on the cream theme. `ProjectStory.tsx` is the screenshot-led one, drawn from the **story frames** of the July 2026 file (`5mDT1eQf2KBcET9dh6kPXd`, section `58:3085` for Phanttom and The Forge, node `58:2132` for the newer D2 Stat Builder frame): a centered 688px title block, then centered rows, plus an optional wall of chat screenshots on a tinted band and a closing orange card. A project opts into it by setting `landing` in `projects.ts`.

`StorySection` is a discriminated union of row kinds: `columns` puts shots side by side with Body/L captions underneath (The Forge), `row` seats one shot beside its 18px caption (Phanttom), `copy` is a Heading/L + 18px block on the same 688px column as the title (D2), `shot` stands one screenshot on its own with an optional panel laid over it (D2's table + sort panel), `band` is the full-bleed closing block (no3y Code's "Learning to Design Engineer"), and `tracks` is Crisp's timeline legend — discarded one-bar player optional via `attempt`, then the five-track shot and a labelled row per track. `landing.eyebrow` takes an array to get the file's hairline-split row; `feedback.body` and `outro` are both optional.

A `feature` or `copy` body is `Prose` — a string, or paragraphs where any one can be `TextRun[]` instead of plain text. A run carries `strong` (semibold + underlined), `muted` (dropped to `--color-text-muted`) and `href`, which underlines and routes in-app for a `/work/…` target or opens a tab otherwise.

The page has no padding of its own, because the feedback band's tint runs edge to edge — `landing.flow` picks the rhythm instead. `banded` (the default) gives every row its own **120px gutter with 80px rows**. `continuous` (D2, no3y, Crisp) runs the title block, the hero shot and every row in one 80px-padded block. Row and column widths are px at the 1272px content width, rendered as `fr` shares. The shared `shellPad()` gutter caps the column at `SHELL_MAX` (1600). `landing.hero.shot` is the app window under the copy block; a looping clip uses `video` instead (`StoryClip` / `HeroVideo`). The Back pill hangs 70px off the copy column's left edge rather than the page's.

The password for the Invisible career work lives on the case study pages, not on a separate index. `WorkGate` is the form; `src/workGate.ts` holds the `sessionStorage` key and `isUnlocked` / `unlock`. A locked visitor who opens `/work/invisible/onboarding`, `/work/invisible/synapse` or `/work/invisible/apply` sees the form on that URL and the content after they unlock. `/work/invisible` itself redirects to `/work`. This is a soft client-side gate — anything served to `/work/*` assets is still public, so don't put truly private material in `public/work/`. Path routes need a host SPA fallback — `vercel.json` rewrites unknown paths to `index.html`.

`InvisibleOnboarding.tsx`, `InvisibleSynapse.tsx` and `InvisibleApply.tsx` are hand-built rather than data-driven. They run `ProjectStory`'s `continuous` flow with stacked rows: a centred 700px column for the title block and for each row's heading + copy, 80 from that copy down to its media. Each keeps a local `mediaWidth()`. The gutter is symmetric (`shellPad()` either side). Rows carry their own `lead` (`tight` at 120 when a row continues the heading above it).

Project copy lives in `src/data/projects.ts`, not in components — `ProjectLanding` and `ProjectStory` read from it, so adding a project page is a data-only change.

`WorkList.tsx` is the Work tab: a two-column grid of cards (one column on mobile). The cards and sections live in `src/data/workCards.ts`; the rail's Work menu and the grid both read `WORK_FILTERS`. Desktop has no filter pills — those sit in the rail. Mobile shows a pill row over the grid. Each card is its Figma export plus a caption (title, muted subtitle, a "Case study" or "View" pill, and an optional extra action or "@ Invisible Technologies" label). Changing the filter updates the grid in place; the panel's `tab-content-in` entrance still runs when switching onto the Work tab.

## Styling conventions

- Tailwind v4 is wired via `@tailwindcss/vite` and imported in `src/index.css`, but **most components use inline `style={{ ... }}` objects, not Tailwind classes**. Match the surrounding file's style when editing — don't refactor inline styles to Tailwind unless asked.
- **Design tokens are the single source of truth**, declared as CSS vars in `src/index.css` and mirrored by the Figma "Mini Design System" page (file `5mDT1eQf2KBcET9dh6kPXd`, node `25:800`). Change one, change the other.
  - Colors: surfaces (`--color-bg-primary`, `-raised`, `-inverse`, `-cream`, `-tint` — a translucent lift that stacks, which is how `ProjectStory`'s feedback band and the wall inside it are built), text on the dark shell (`--color-text-primary`, `-secondary`, `-muted`, `-inverse`), ink on the cream column (`--color-ink`, `-secondary`, `-muted`), borders (`--color-border-subtle`, `-default`, `-ink`), accent (`--color-orange`, `-hover`, `--color-on-accent`).
  - Spacing: `--space-xs` (4) through `--space-5xl` (80). Radius: `--radius-sm` (6) through `--radius-4xl` (56), plus `--radius-full` for pills. Control heights: `--control-xs` (28), `--control-sm` (32), `--control-md` (36), `--control-lg` (40).
  - Per-file constants stay as the naming pattern, but they now point at vars (`const CREAM_BG = 'var(--color-bg-cream)'`), so no component re-declares a hex. New components should follow the same pattern.
  - `src/design-system/tokens.ts` exports the same tokens as typed objects for inline styles, plus the `type` ramp.
- Reach for a token rather than a raw px value for radii and gaps. The known exceptions are `ProjectStory`'s `FRAMED_RADIUS` (an optical +1 on `MOCKUP_RADIUS`, for a `framed` shot whose border draws outside the clip — derived from `radiusPx` rather than written as a literal), `borderRadius: '50%'` for true circles, and page-level gutters, which are layout rather than component spacing.
- **Every mockup across the project pages shares one outer radius**, `ProjectStory`'s `MOCKUP_RADIUS` (`radius.xl`, 16). Anything whose surface is a screenshot, a video or a chart lands on it. Chrome *inside* a mockup keeps its own smaller radius.
- Font is `Geist Variable` from `@fontsource-variable/geist`, set globally on `body`. The ramp lives in `tokens.ts` as `type['display-xl' | 'heading-l' | 'body-l' | 'label-m' | 'eyebrow' | ...]`.
- Buttons come from `src/design-system/` (`Button`, `IconButton`) and icons from `@phosphor-icons/react`. `@noey-17/yearn-ui`'s stylesheet is still imported in `App.tsx`, but nothing renders its components any more; `ProjectLanding` still imports `@untitledui/icons` per-icon (`@untitledui/icons/ArrowDown`).
- `Button` renders a `<button>`, so a link that should look like one is hand-styled rather than wrapped — `ProjectStory`'s Back anchor pulls its palette from `buttonStyles`' `VARIANTS.ghost` so it can't drift from the real thing. Do the same rather than nesting a `Button` inside an `<a>`.

## Design system

`src/design-system/` holds the code half of the system: `tokens.ts` (colors, spacing, radius, control heights, type ramp), `icons.ts` (the 17 Phosphor icons that exist as Figma components), `buttonStyles.ts` (the palette/state matrix shared by both buttons), `Button.tsx` and `IconButton.tsx`, and the `*.stories.tsx` files that document them. `docs.tsx` is story-only chrome and is not shipped in the app.

`IconButton` is a **separate component**, not a variant of `Button` — folding it in would have doubled the set to 54 variants and allowed the invalid icon-only-plus-label combination. It is circular (width locked to the control height), takes a required `label` prop that renders as `aria-label`, and shares `Button`'s palette through `buttonStyles.ts`, so the two cannot drift. Figma mirrors this with a separate `Icon Button` component set.

`Button.tsx` is the system's button and is what Storybook documents. It is sized by **fixed height** (`--control-xs/sm/md/lg` = 28/32/36/40) rather than vertical padding, so a row of buttons lines up regardless of label or icon; only the horizontal padding varies by size. Each size pairs a label style and an icon size in `SIZES` / `ICON_SIZE` — `xs` drops to a 12px label and a 14px icon so the icon stays in proportion. `ContactMenu` and every control in `WorkList` use it; `@noey-17/yearn-ui`'s `Button` is no longer used anywhere, though the package's stylesheet is still imported in `App.tsx`.

Icons are Phosphor at **duotone** weight. The weight is set once via `IconContext` in `src/main.tsx` (and in `.storybook/preview.tsx`) from `ICON_DEFAULTS` in `design-system/icons.ts` — don't pass `weight` at call sites. Each duotone icon is a 20%-opacity tint path behind a solid main path; the Figma `Icon / *` components mirror this with `Tint` and `Main` layers. `ProjectLanding` still uses `@untitledui/icons` (`ArrowNarrowLeft`, `ArrowNarrowRight`), which are not part of the system and are unaffected by the Phosphor context.

Storybook config is in `.storybook/`. `main.ts` strips the `figma-capture-dev-only` Vite plugin, which is for the app's `/send-to-figma` flow and has no business in Storybook.
