# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — Vite dev server (HMR)
- `npm run build` — production build to `dist/`
- `npm run typecheck` — `tsc -b` (strict, with `noUnusedLocals`, `noUnusedParameters`, `erasableSyntaxOnly`)
- `npm run lint` — ESLint across the repo
- `npm run preview` — preview the production build
- `npm run storybook` — Storybook on :6006, documenting the design system

There is no test runner configured.

## Architecture

Single-page React 19 + Vite 8 portfolio. There is **no router library** — `src/App.tsx` reads `window.location.pathname` and switches the rendered tree. Internal links use hrefs like `/work/invisible` via `AppLink` / `navigate`. When adding a new route, extend the conditional in `App.tsx` and link to `/your-route`. Legacy `#/…` bookmarks are rewritten to pathnames on boot.

The route is read through `useSyncExternalStore(subscribeToRoute, getRoute)` rather than a `useState` + listener effect, because a page that redirects from its **own mount effect** fires `routechange` before an effect in `App` could have subscribed. `useSyncExternalStore` re-reads after subscribing, so that update isn't dropped; with the listener in an effect it was, and the redirect left a blank page. `navigate(path, { replace })` is for those same self-redirects: pushing the page being bounced away from would only send the visitor forward again on Back. The leftover `/work/invisible` index is one of those — `App` replaces it with `/work`.

Routes:

| Route | Renders |
|---|---|
| `/` | Me tab — `Hero`, then `Experience` and `LlmWall` below the fold |
| `/work` | Design tab — `WorkList`, the filtered project list |
| `/work/<slug>` | `ProjectStory` if `projects[slug].landing` is set, otherwise `ProjectLanding` (`src/data/projects.ts`) |
| `/work/invisible` | Redirects to `/work` (the old case-study index is gone) |
| `/work/invisible/onboarding` | `InvisibleOnboarding` — the Meridial onboarding case study |
| `/work/invisible/synapse` | `InvisibleSynapse` — the Synapse 0-1 launch case study |

The two tabs come from the **"R2 Dark" section** of the July 2026 Figma file (`5mDT1eQf2KBcET9dh6kPXd`, node `49:10903`), which turned the whole shell dark and replaced the Work bento with a list. `ProjectStory` (D2 Stat Builder, Phanttom, The Forge, no3y Code) is dark and has its own frames (section `58:3085`). `ProjectLanding` is **still cream** — nothing links to it from `WorkList` today, but it will look wrong the moment something does.

`App.tsx` is one normally-scrolling dark page, not a fixed 100vh split. `ShaderPanel` — `ShaderEffect` (a WebGL animated gradient via the `shaders` package — `FlowingGradient` + `Dither`) with the headline overlaid — is absolutely positioned one viewport tall in the top-right corner and the page scrolls past it. The content column is 58.3vw on Me and 87.3vw on Design (`CONTENT_PCT`), animating between them; the shader is anchored at `left: 58.3vw; right: 0`, so widening the column slides it under the panel rather than squishing it. Both widths come from the Figma frames (881 and 1320 of 1512). Because those are shares of the viewport they keep widening on a big screen while the copy inside stays on its own measure, which would pin the text to the far left of a large empty column — so `src/layout.ts` grows the **left gutter** past the design width: `shellPad()` is `max(120px, (100vw − SHELL_MAX) / 2)` with a single `SHELL_MAX` of 1600 (`ProjectStory`'s cap, the site's widest page). There is deliberately one shared formula, anchored to `100vw` rather than the container, so **every route resolves the same left edge at any viewport width** — centring each page against its own content width gave every route a different left edge on a big screen and the tabs and copy jumped sideways on navigation. Pages with narrower content left-align to that edge and keep their own max-widths (`WorkList` caps its list at the file's 1240, `WORK_LIST_MAX`). The right gutter inside the tab columns stays the fixed 120 (`PAGE_GUTTER`) — the shared inset is viewport-centred, and mirroring it inside a column narrower than the viewport would eat the content's width. `App` passes the inset to `Header`, so the tabs and profile row hold the same edge, and `Experience` pads itself with it because it sits outside the page body. `Header`'s `trailingInset` is the right-side counterpart for the pinned Contact menu: the tabs pass the fixed gutter (their header lives inside the column), while full-width pages leave it defaulting to `barInset` so their Contact sits symmetric with the left edge.

`Header` is the shared chrome on every page: the `TabBar` (Me / Design, orange underline on the active tab) with `ContactMenu` pinned right, and the profile row below. Pages that already pad themselves pass `barInset="0" contentInset="0"`; `showProfile={false}` drops the profile row, which is what the Design tab does. The **second tab is labelled "Design" but still routes to `/work`**, so existing links keep resolving.

`Footer.tsx` is **not mounted anywhere** — commit `7627598` removed it sitewide and left the component file in place. The story frames in Figma (including no3y Code's) still draw it, so a frame ending in a Back to / Jump to / Get in touch block is expected to diverge. What follows describes the component as built, should it ever come back. It comes from the July 2026 file (node `58:2190`): three columns on an 80px pad with a 120px gutter, Back to / Jump to / Get in touch. It runs the **full page width**, so `App.tsx` renders it as a sibling of the content column rather than inside it (the Me tab's column is only 58.3vw). The email row copies to the clipboard and confirms with a check rather than navigating, and "Moonfang Armory" points at the live site because `/work/armory` still falls through to the cream `ProjectLanding`. Two divergences from the file: it seats the first column's links 12px under their heading against the other two columns' 32 — all three run on 32 here — and the Jump-to column is `min-width: 153px` because "Moonfang Armory" overflows the file's 153.

Project pages come in two layouts. `ProjectLanding.tsx` is the generic one — stats row, `label`-railed sections, stack and status grids — and is still on the cream theme. `ProjectStory.tsx` is the screenshot-led one, drawn from the **story frames** of the July 2026 file (`5mDT1eQf2KBcET9dh6kPXd`, section `58:3085` for Phanttom and The Forge, node `58:2132` for the newer D2 Stat Builder frame): a centered 688px title block, then centered rows, plus an optional wall of chat screenshots on a tinted band and a closing orange card. A project opts into it by setting `landing` in `projects.ts`.

`StorySection` is a discriminated union of five row kinds: `columns` puts shots side by side with Body/L captions underneath (The Forge), `row` seats one shot beside its 18px caption (Phanttom), `copy` is a Heading/L + 18px block on the same 688px column as the title (D2), `shot` stands one screenshot on its own with an optional panel laid over it (D2's table + sort panel), and `band` is the full-bleed closing block — a wallpaper with copy over a darkened left edge and a screenshot beside it (no3y Code's "Learning to Design Engineer"). The band's scrim is a plain gradient whose stops are measured off the rendered frame, because the file draws it as a blurred wedge whose exported CSS lands about half as wide. `landing.eyebrow` takes an array to get the file's hairline-split row ("Vibe coded | Figma+Cursor+Claude"); `feedback.body` and `outro` are both optional, and the D2 frame drops the orange card entirely.

A `feature` or `copy` body is `Prose` — a string, or paragraphs where any one can be `TextRun[]` instead of plain text. A run carries `strong` (semibold + underlined, how the file marks a project name), `muted` (dropped to `--color-text-muted`, which the file does for the clause after that name) and `href`, which underlines and routes in-app for a `/work/…` target or opens a tab otherwise. no3y Code's "the idea" is the only row using it, and an `eyebrow` entry takes runs too, for its "Fork of **T3 Code**".

The page has no padding of its own, because the feedback band's tint runs edge to edge — `landing.flow` picks the rhythm instead. `banded` (the default, and the Phanttom and Forge frames) gives every row its own **120px gutter with 80px rows**, so consecutive rows sit 184px apart with the page container's 24px gap between them. `continuous` (the D2 frame) runs the title block, the hero shot and every row in one 80px-padded block on an 80px gap, with the bands below butted straight against it. Row and column widths are px at the 1272px content width, rendered as `fr` shares of a proportional row, so shots, captions and gaps scale together; the feedback wall is the same trick, so its cards fill the column instead of wrapping. Because those shares are measured off a column the page sizes from the viewport, the column would keep stretching on a big screen: the shared `shellPad()` gutter caps it at `SHELL_MAX` (1600, measured off this page) and hands the slack to the gutters, written as padding rather than a capped wrapper so the feedback band's tint still runs edge to edge. `landing.hero.shot` is the app window under the copy block, and `heroWidth` keeps it on the same share of the column as the rows rather than a fixed px cap, which would leave the hero pinned while everything under it grew. The Back pill is kept deliberately even though the frames drop it, and hangs 70px off the copy column's left edge rather than the page's, so it keeps that gap at any width. A `shot` section's `width`/`height` is the whole composition's footprint and `frame` / `overlay` are px boxes inside it, so an overlapping panel keeps its overlap as the group scales. The Forge's outro sets `large` for the file's 40px heading (`display-l`); the other cards stay on Heading/L.

Four optional knobs exist only because no3y Code's frame (`149:12222`) splits things the other three hold together, so leaving them unset reproduces Phanttom / Forge / D2 exactly. `rowGap` spaces the rows apart from `gap`, which stays the title-to-hero distance (120 into the rows, then 200 between them). `rowAlign` centres the rows while `align: 'start'` keeps the title left, which is what seats that frame's 1225-wide composer row inside the 1272 column. `titleRhythm: 'paired'` runs the title block on 24px and seats the eyebrow flush against the title as its own group (the file's Frame 465), against the `even` 16px that Phanttom and Forge use throughout. The row heading-to-copy gap is 24 in **every** frame, so it is not a knob.

Figma sizes the browser frames by fixed height and clips the capture inside; our `browser-bar.png` renders at a different ratio to Figma's bar, so each shot's `aspect` is `designed total height − our bar at that width` and the frames land on their designed heights. `LandingShot.zoom` is for the shots the file crops into rather than fits (the table runs at 1.366× its frame). `FRAME_BORDER` / `FRAME_BG` / `OVERLAY_BORDER` are the screenshots' own chrome, not theme surfaces, so they stay hexes.

The password for the Invisible career work lives on the case study pages, not on a separate index. `WorkGate` is the form; `src/workGate.ts` holds the `sessionStorage` key and `isUnlocked` / `unlock`. A locked visitor who opens `/work/invisible/onboarding` or `/work/invisible/synapse` (from a Career card, a Me-tab quick hit, or a cold URL) sees the form on that URL and the content after they unlock, so Back is the page they came from — the Design tab's Career bento, not a leftover index. `/work/invisible` itself redirects to `/work`. This is a soft client-side gate — anything served to `/work/*` assets is still public, so don't put truly private material in `public/work/`. Path routes need a host SPA fallback — `vercel.json` rewrites unknown paths to `index.html`.

`InvisibleOnboarding.tsx` and `InvisibleSynapse.tsx` are hand-built rather than data-driven, because their copy and diagrams have no home in the `Project` type. Both run the same shape from their Figma frames (`58:2190`-era dark shell; Synapse is node `247:27494`): a 720px title block over a 1225 column of copy-left / media-right rows on an 80px gutter. Synapse's frame splits that 1225 differently per row (412/733, 413/732, 388/757), so the widths ride on the row as `fr` shares rather than living on the page. Its "legacy platform" diagram is drawn in the file rather than captured, so it's rebuilt as percentage-positioned boxes the way the onboarding charts are, and the component-library band sets its padding and the gaps between shots as percentages of the panel width so the inset holds its proportion as the column narrows. Tailwind's preflight strips list markers, so the numbered list in "the problem" sets `listStyleType` back on explicitly.

Project copy lives in `src/data/projects.ts`, not in components — `ProjectLanding` and `ProjectStory` read from it, so adding a project page is a data-only change.

`WorkList.tsx` is the Design tab: a filter rail beside whatever the active filter renders. Unlike the pages above it, **its contents are declared in the file itself** (`career`, `graphic`, and the `FILTERS` array), pulling titles off `projects.ts` where they exist — the cards carry art, copy and links that have no home in the `Project` type. Each filter picks a `layout`: `bento` is Personal projects' featured-plus-stack, `even` is a plain grid of equal cards (Career and Graphic Design), and `list` is the divided rows. **Nothing selects `list` today** — `Row` / `ProjectRow` are still here for the next filter that wants them. The rail sits in a `max-content` grid column with an 80px gutter, matching the file's 80 / 194 / 1240 columns; mobile drops the grid and wraps the rail into a row.

The Personal bento runs on `TexturedBentoCard` (R3 page, Figma node `273:39477`): a **live** dither well — a `shaders/react` FlowingGradient under a source-coloured Dither, the hero's recipe at half speed and a finer `pixelSize` of 3, each palette one colour family per project — inside a 4px `CARD_CREAM` frame, with the screenshots floating on top. The Figma frame's fill stack is texture PNGs under tints; the shader replaces it wholesale, so the cards animate. Shot widths and the featured card's 32px inset and gutter are written as percentages of the file's 569.342 / 380.657 card widths so the composition scales with the column. The layout diverges from the frame's heights on purpose: the featured card runs 569.342×583 — a quarter shorter than the height that would square the two cards beside it, so they sit slightly landscape at 380.657×283.5 — and each **card owns its aspect ratio** (the well is plain flex fill) so the hover reveal shrinks the art instead of ever resizing the card. The no3y panels are exported at their full node heights — the sidebar runs past the well's bottom edge and clips — and the shots layer is absolute inside the well so that overflow can never size the card. The file's 4px cream frame is the card's **padding**, not a border, which is what lets these share the cream cards' hover reveal — the textured well is the mask, and hovering slides it up to show the title on the cream backdrop, driven by the same `.work-bento-art-first` / `.work-bento-reveal-title` CSS; `.work-bento-tex` only re-bases `--bento-shown-pad` to 4px so the frame stays hairline at rest. `BentoLink` takes an `accent` each card fills with its palette's base, which recolours the hover outline and arrow through `--bento-accent`. The even filters (Career and Graphic Design) run the same `TexturedBentoCard` at the small-card ratio, one `BentoItem.shader` palette per card — the older cream `BentoCard` is gone.

Career is the Invisible work, one card per case study, captioned by the client (`eyebrow: 'Invisible'`) rather than by project type. The cards link straight to each study; that page shows `WorkGate` when locked. They are the personal cards' `TexturedBentoCard` — same frame, same `380.657 / 283.5` ratio, same reveal, same live dither well — with `BentoItem.shader` carrying each study's palette. The art (`public/work/bento/shot-invisible-*.png`, the bare window cropped out of each study's screenshots) floats over it at `shotWidth` — a window on a baked plate would sit as a flat slab over the shader.

## Styling conventions

- Tailwind v4 is wired via `@tailwindcss/vite` and imported in `src/index.css`, but **most components use inline `style={{ ... }}` objects, not Tailwind classes**. Match the surrounding file's style when editing — don't refactor inline styles to Tailwind unless asked.
- **Design tokens are the single source of truth**, declared as CSS vars in `src/index.css` and mirrored by the Figma "Mini Design System" page (file `5mDT1eQf2KBcET9dh6kPXd`, node `25:800`). Change one, change the other.
  - Colors: surfaces (`--color-bg-primary`, `-raised`, `-inverse`, `-cream`, `-tint` — a translucent lift that stacks, which is how `ProjectStory`'s feedback band and the wall inside it are built), text on the dark shell (`--color-text-primary`, `-secondary`, `-muted`, `-inverse`), ink on the cream column (`--color-ink`, `-secondary`, `-muted`), borders (`--color-border-subtle`, `-default`, `-ink`), accent (`--color-orange`, `-hover`, `--color-on-accent`).
  - Spacing: `--space-xs` (4) through `--space-5xl` (80). Radius: `--radius-sm` (6) through `--radius-4xl` (56), plus `--radius-full` for pills. Control heights: `--control-xs` (28), `--control-sm` (32), `--control-md` (36), `--control-lg` (40).
  - Per-file constants stay as the naming pattern, but they now point at vars (`const CREAM_BG = 'var(--color-bg-cream)'`), so no component re-declares a hex. New components should follow the same pattern.
  - `src/design-system/tokens.ts` exports the same tokens as typed objects for inline styles, plus the `type` ramp.
- Reach for a token rather than a raw px value for radii and gaps. The known exceptions are the 9px inner radius in `ProjectStory`'s `BrowserFrame` (an optical inset against its 8px outer frame), `borderRadius: '50%'` for true circles, and page-level gutters, which are layout rather than component spacing.
- Font is `Geist Variable` from `@fontsource-variable/geist`, set globally on `body`. The ramp lives in `tokens.ts` as `type['display-xl' | 'heading-l' | 'body-l' | 'label-m' | 'eyebrow' | ...]`.
- Buttons come from `src/design-system/` (`Button`, `IconButton`) and icons from `@phosphor-icons/react`. `@noey-17/yearn-ui`'s stylesheet is still imported in `App.tsx`, but nothing renders its components any more; `ProjectLanding` still imports `@untitledui/icons` per-icon (`@untitledui/icons/ArrowDown`).
- `Button` renders a `<button>`, so a link that should look like one is hand-styled rather than wrapped — `ProjectStory`'s Back anchor pulls its palette from `buttonStyles`' `VARIANTS.ghost` so it can't drift from the real thing. Do the same rather than nesting a `Button` inside an `<a>`.

## Design system

`src/design-system/` holds the code half of the system: `tokens.ts` (colors, spacing, radius, control heights, type ramp), `icons.ts` (the 17 Phosphor icons that exist as Figma components), `buttonStyles.ts` (the palette/state matrix shared by both buttons), `Button.tsx` and `IconButton.tsx`, and the `*.stories.tsx` files that document them. `docs.tsx` is story-only chrome and is not shipped in the app.

`IconButton` is a **separate component**, not a variant of `Button` — folding it in would have doubled the set to 54 variants and allowed the invalid icon-only-plus-label combination. It is circular (width locked to the control height), takes a required `label` prop that renders as `aria-label`, and shares `Button`'s palette through `buttonStyles.ts`, so the two cannot drift. Figma mirrors this with a separate `Icon Button` component set.

`Button.tsx` is the system's button and is what Storybook documents. It is sized by **fixed height** (`--control-xs/sm/md/lg` = 28/32/36/40) rather than vertical padding, so a row of buttons lines up regardless of label or icon; only the horizontal padding varies by size. Each size pairs a label style and an icon size in `SIZES` / `ICON_SIZE` — `xs` drops to a 12px label and a 14px icon so the icon stays in proportion. `ContactMenu` and every control in `WorkList` use it; `@noey-17/yearn-ui`'s `Button` is no longer used anywhere, though the package's stylesheet is still imported in `App.tsx`.

Icons are Phosphor at **duotone** weight. The weight is set once via `IconContext` in `src/main.tsx` (and in `.storybook/preview.tsx`) from `ICON_DEFAULTS` in `design-system/icons.ts` — don't pass `weight` at call sites. Each duotone icon is a 20%-opacity tint path behind a solid main path; the Figma `Icon / *` components mirror this with `Tint` and `Main` layers. `ProjectLanding` still uses `@untitledui/icons` (`ArrowNarrowLeft`, `ArrowNarrowRight`), which are not part of the system and are unaffected by the Phosphor context.

Storybook config is in `.storybook/`. `main.ts` strips the `figma-capture-dev-only` Vite plugin, which is for the app's `/send-to-figma` flow and has no business in Storybook.
